## 摘要
LLM智能体会将智能体观测结果（如工具输出、shell日志和文件读取）附加到发送给提供方的转录本中，从而泄露隐私（例如路径、电子邮件）和凭据（例如API密钥）。现有的占位符脱敏方法存在缺陷：它可能遗漏嵌入的或跨轮次的引用，过度脱敏无害的相似内容，并破坏有助于推理的结构。我们提出了SlotGuard，这是一个本地转录本边界，可以在隐藏敏感数据的同时保持智能体的性能。SlotGuard将结构化绑定重写为带类型的、后缀感知的槽位，用保持格式的合成值替换秘密，通过轻量级会话图链接跨轮次引用，并仅在可信运行时内部恢复原始值。在受控的面向仓库的智能体转录本上，SlotGuard移除了所有20,814个注释的结构敏感字符（涉及9,229个路径），并将852个植入值中的凭据泄露降至0.0%。在四个上游模型上，它保持接近原始转录本的任务成功率，而通用脱敏则降至2.5%。转录本重写的每轮中位数时间为14.424微秒。代码公开在https://github.com/illinoisdata/SlotGuard。

## Abstract
LLM agents can leak privacy (e.g., paths, emails) and credentials (e.g., API keys) as agent observations (e.g., tool outputs, shell logs, and file reads) are appended to provider-bound transcripts. Existing placeholder redaction is brittle: it can miss embedded or cross-turn references, over-redact benign lookalikes, and destroy the structure useful for reasoning. We present SlotGuard, a local transcript boundary that can hide sensitive data while retaining agents' performance. SlotGuard rewrites structural bindings as typed, suffix-aware slots, replaces secrets with format-preserving synthetic values, links cross-turn references with a lightweight session graph, and restores raw values only inside the trusted runtime. On controlled repository-oriented agent transcripts, SlotGuard removes all 20,814 annotated structurally sensitive characters across 9,229 paths and reduces credential leakage to 0.0\% across 852 planted values. It remains close to raw-transcript task success across four upstream models, while generic redaction drops to 2.5\%. Transcript rewriting takes a median of 14.424~$μ$s per agent turn. The code is publicly accessible at https://github.com/illinoisdata/SlotGuard.

# 论文总结：SlotGuard: Stop Oversharing Private Local Context in LLM Agent Transcripts

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：LLM agent 在执行任务时，会将本地工具输出、shell日志、文件读取等观测结果附加到发送给模型提供商的转录本中。这些转录本可能包含绝对路径、内部主机名、环境变量、API密钥等敏感数据。现有基于占位符的脱敏方法（如用 `PATH` 或 `API_KEY` 替换）存在三大缺陷：
  - **遗漏**：无法发现嵌入在shell参数展开、进程列表等上下文中的秘密。
  - **过度脱敏**：误删看似敏感但实际无害的字符，或破坏路径结构、文件扩展名等对Agent推理至关重要的信号。
  - **结构破坏**：占位符使模型无法理解值的类型、位置和语法，导致工具调用失败。
- **整体含义**：需要在本地运行时与模型提供商之间建立一个**兼容性保持的隐私边界**，既能隐藏私有值，又能保留Agent所需的执行线索（如路径形状、文件类型、凭据格式），从而在不牺牲任务性能的前提下保护隐私。

## 2. 方法论：核心思想与关键技术细节
- **核心思想**：在Agent运行时与上游模型之间插入一个本地边界（SlotGuard），将敏感值替换为稳定、类型化的引用（槽），仅在可信本地执行时恢复原始值。
- **关键技术**：
  - **两层级检测器**：
    - **同步规则引擎**：高精度处理已知模式（路径前缀、邮箱、令牌等）。
    - **异步本地模型（可选）**：处理语义敏感文件名、实体名称等难以规则化的场景，仅提出候选，由主引擎验证后应用。
  - **兼容性保持重写**：
    - **结构化绑定（路径、邮箱等）**：使用**后缀感知的抽象**，例如保留文件扩展名和最后几个安全后缀，用 `[REPO_ROOT_1]` 等命名槽替换敏感部分。槽通过HMAC生成，会话内稳定、会话间不可链接。
    - **秘密值（API密钥、密码等）**：使用**格式保持的合成置换（FPS）**，从相同格式类中均匀采样合成值（如保持 `sk-...` 结构），确保合成值不携带原始秘密的任何字符。
  - **跨轮追踪**：维护**会话级槽表**和**语义实体图（SEG）**，记录受保护值与其嵌入、派生、后续关键词引用之间的链接，扩展保护范围。
  - **有防护的重绑定**：仅在本地工具调用时，检查槽是否在表中、类型是否正确、作用域是否允许，才恢复原始值；拒绝未知、伪造、越界或包含shell元字符的句柄。
- **流程**（文字说明）：
  1. 转录本提交前，规则引擎/本地模型识别敏感跨度。
  2. 结构化绑定替换为带类型的槽（如 `[REPO_ROOT_1]/legal/[SENSITIVE_DOC_1].pdf`），秘密替换为FPS合成令牌。
  3. 槽表记录映射，SEG记录关联关系。
  4. 模型返回响应后，在本地执行时，根据槽表和重绑定规则恢复原始值，执行工具调用，且不将原始值写回转录本。

## 6. 主要结论与发现
- **隐私保护**：SlotGuard完全消除结构敏感字符泄露（20,814个字符全部移除），凭据会话泄露率从100%降至0%，凭据值泄露率从23.5%（最佳基线）降至0%。

- **鲁棒性**：所有9229个路径往返正确，64个无效重绑定尝试均被拒绝。
