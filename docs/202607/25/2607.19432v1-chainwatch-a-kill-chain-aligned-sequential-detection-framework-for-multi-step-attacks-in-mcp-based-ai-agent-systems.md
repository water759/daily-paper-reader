## 摘要
模型上下文协议（MCP）是一种开源标准，允许AI代理连接到外部工具、数据库和服务。虽然这种连接性赋予了代理强大的能力，但也引入了多步攻击，现有的每次调用防御机制无法可靠地检测到这些攻击。攻击者可以将单个看似无害的工具调用组合成恶意序列，从而逃避孤立检查。本文提出了ChainWatch，一种用于识别基于MCP的AI代理系统中多步攻击的序列检测框架。ChainWatch使用六阶段杀伤链对攻击过程进行建模，并应用隐马尔可夫模型（HMM）对工具调用序列进行分类。当会话在多个阶段表现出可疑进展时，检测规则将被触发。该框架由结构化的威胁模型支持，涵盖直接序列攻击、间接提示注入链以及混合多阶段攻击。一个20维特征提取模式从工具交互中捕获行为信号。我们使用安全文献中的五个代表性攻击场景展示了该方法，说明了ChainWatch如何检测逃避传统单次调用安全机制的攻击链。

## Abstract
The Model Context Protocol (MCP) is an open-source standard that allows AI agents to connect to external tools, databases, and services. While this connectivity enables powerful agent capabilities, it also introduces multi-step attacks that existing per-call defenses cannot reliably detect. Attackers can compose individually benign tool invocations into malicious sequences that evade isolated inspection. This paper presents ChainWatch, a sequential detection framework for identifying multi-step attacks in MCP-based AI agent systems. ChainWatch models attack progression using a six-stage kill chain and applies a Hidden Markov Model (HMM) to classify tool-call sequences. Detection rules are triggered when a session exhibits suspicious progression across multiple stages. The framework is supported by a structured threat model covering direct sequential attacks, indirect prompt injection chains, and hybrid multi-stage attacks. A 20-dimensional feature extraction schema captures behavioral signals from tool interactions. We demonstrate the approach using five representative attack scenarios from the security literature, showing how ChainWatch detects attack chains that evade traditional per-call security mechanisms.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：模型上下文协议（MCP）是Anthropic于2024年11月发布的开源标准，使AI代理能够无缝连接外部工具、数据库和服务。截至2026年7月，MCP已有数千个活跃服务器，集成到Cursor、Claude Desktop、GitHub Copilot等主流平台，并由Linux基金会管理。然而，MCP的安全防护发展滞后——超过50个CVE已被记录，近半数部署服务器存在认证问题。
- **核心问题**：现有MCP安全防御（如MCPShield、MCP-Guard、MindGuard）均针对单次调用或单服务器威胁模型设计。它们无法检测一种关键威胁——**多步攻击**：攻击者将多个单独无害的工具调用组合成恶意序列（例如：查询余额→列出收款人→添加攻击者控制的收款人→转账），每个步骤都通过了逐调用检查，但序列整体具有恶意意图。STAC研究表明此类链式攻击在GPT-4.1上成功率超过90%；Promptware杀伤链分析发现21/36种AI代理攻击跨越4个或更多阶段。
- **整体含义**：MCP系统的安全需要从“逐调用防御”升级到“序列行为检测”，即把会话级别的调用序列视为一个整体信号，识别隐藏的攻击进程。ChainWatch正是针对这一空白提出的首个序列化检测框架。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
ChainWatch作为透明代理层位于MCP客户端与服务器之间，不修改模型、宿主或服务器。它观察每个工具调用和响应，通过**杀伤链对齐**的序列检测，识别跨会话的多步攻击进度。

### 关键技术细节

#### （1）威胁分析与攻击分类
- **部署模型**：ChainWatch作为静默拦截层，MCP客户端和宿主应用被视为可信，MCP服务器被视为潜在恶意。
- **攻击者能力**：可以注册/攻陷MCP服务器、嵌入恶意内容、替换工具定义、协调跨服务器步骤，但无法访问客户端内部、改变底层模型行为或修改检测阈值。
- **三类攻击**：
  - **直接序列攻击（DSA）**：一系列单独允许的请求组合实现恶意目标（如金融欺诈链）。
  - **间接注入链（IIC）**：恶意指令嵌入外部数据（如GitHub Issue），代理自动处理并执行后续调用。
  - **混合多阶段攻击（HMSA）**：服务器端操控结合注入传播跨代理实例（如配置写入导致跨代理特权升级）。

#### （2）MCP杀伤链（六阶段）
| 阶段 | 名称 | 关键可观察特征 |
|------|------|----------------|
| 1 | 侦察 | tools/list调用、参数稀疏、快速工具采样 |
| 2 | 信任建立 | 良性模式、低敏感度、无跨服务器调用 |
| 3 | 注入 | 输出中的指令文本、XML标签、描述不匹配 |
| 4 | 升级 | READ到WRITE的转换、敏感度上升、链式数据 |
| 5 | 横向移动 | 跨服务器调用、.mcp.json编辑、代理生成 |
| 6 | 数据外泄 | READ到NETWORK的链、通信工具携带数据 |

#### （3）特征提取层
将每次工具调用转换为**20维数值向量**，分为5组：
- **工具类别（TC，5维）**：独热编码表示READ、WRITE、EXECUTE、NETWORK、CONFIGURE
- **参数敏感度（PS，1维）**：对凭证、路径、URL、编码数据加权求和
- **数据流（DF，4维）**：二元标记：内部读取、外部写入、链式传播、跨服务器
- **时间特征（TF，3维）**：调用间隔、单位时间调用率、会话时长
- **输出特征（OC，7维）**：指令文本、XML标签、描述-输出不匹配、体积异常、哈希变更、编码数据、外部URL

#### （4）杀伤链阶段分类器（HMM）
- **定义**：λ = (S, Σ, A, B, π)，其中S为6个杀伤链状态，Σ为20维观测空间，A为转移矩阵，B为发射分布，π为初始分布。
- **结构约束**：前向转移概率大于后向；跳跃超过两个阶段概率低（符合4-7次调用跨度）；保留小后向概率（攻击者可能重复早期行为）。
- **设计意图**：将Holgado等人的方法从离散IDS告警类型扩展到连续特征向量。

#### （5）序列模式分析器
- 使用**滑动窗口k=10次调用**（超过4-7的跨度），**步阈值m=5**（半窗口内触发）。
- **5条检测规则**：
  - R1（警告）：侦察后直接跟随敏感数据访问
  - R2（警告）：两个或更多服务器被访问且敏感数据流标志激活
  - R3（严重+阻塞）：读取后n步内携带该数据的网络调用（外泄特征）
  - R4（警告）：快速杀伤链加速（阶段跳跃≥2）
  - R5（严重+阻塞）：在阶段4及以上的后阶段写配置
- 所有阈值可配置以适应不同部署的误报容忍度。

## 6. 主要结论与发现

- 现有MCP逐调用防御在多步攻击面前存在结构性的检测盲区——每个非恶意调用单独通过检查，但序列整体构成攻击。
- ChainWatch提出的六阶段杀伤链模型能够将工具调用序列映射为攻击进程状态，通过HMM分类和规则触发实现检测。
- 在5个文献攻击场景中，ChainWatch均能触发警告或严重告警，而现有防御无法发现。
- 该框架是**首个针对MCP系统的序列化多步攻击检测方案**，填补了该领域的空白。
- 实现完整部署的主要障碍在于缺乏标注的会话轨迹数据用于HMM参数校准和阈值调优。

## 7. 优点

- **问题新颖且重要**：准确识别了MCP安全中关键但未受关注的威胁类别，并提供了针对性解决方案。
- **方法设计严谨**：威胁建模细致（三分类攻击模型+六阶段杀伤链），特征提取多维（20维涵盖类别、参数、数据流、时间、输出），HMM结构约束合理（前向偏好、小跳跃、小后向）。
- **可解释性强**：杀伤链阶段和检测规则具有明确语义，便于安全分析师理解和响应。
- **部署友好**：作为透明代理层，无须修改模型、客户端或服务器；可与现有逐调用防御并行运行；支持配置阈值以适应不同误报容忍度。
- **规则设计全面**：覆盖侦察后直接攻击、快速阶段跳跃、外泄链、后阶段写配置等关键攻击模式。

- **可扩展性未验证**：一个代理可能连接数百个服务器，跨服务器数据流跟踪的复杂度可能随服务器数量指数增长。
