## 摘要
威胁建模对于安全软件开发至关重要，然而对云原生架构的手动分析速度缓慢且需要稀缺的安全专业知识。我们提出了ThreatForest，一个多智能体系统，它从源代码仓库生成结构化攻击树，将攻击步骤映射到来自可插拔框架集（MITRE ATT&CK、CAPEC和云特定威胁矩阵）的对手战术、技术和程序（TTP），并综合可操作的缓解措施。ThreatForest将威胁建模分解为多阶段智能体流水线——仓库分析、上下文细化、威胁生成、并行攻击树构建（含TTP映射和缓解综合）以及报告生成——以有向图形式编排，具有确定性验证门、有限重试和三个人机协同验证点。一个领域特定的句子变换器通过余弦相似度将每个攻击步骤映射到候选技术；我们实证表明，这一嵌入阶段，而非周围流水线，是主要的准确性瓶颈。我们在七个应用领域上使用十六维度评分标准评估ThreatForest，由独立LLM评分员小组进行评分，并经过对抗性验证和专家评审。对于威胁陈述、攻击树和缓解措施，小组测得的质量达到0.63-0.68（0-1量表），但仅嵌入的TTP映射只有0.29——这一差距在所有七个领域均稳定，隔离了约束条件。在同一模型上的受控单次调用基线将映射防御性提高了一倍以上，将限制归因于嵌入编码器而非多智能体设计。据我们所知，ThreatForest是第一个将代码仓库转化为跨对手框架的TTP映射攻击树并提供基于证据的缓解措施的端到端系统，同时提供了可复用的基准测试框架。

## Abstract
Threat modeling is essential for secure software development, yet manual analysis of cloud-native architectures is slow and demands scarce security expertise. We present ThreatForest, a multi-agent system that generates structured attack trees from source code repositories, maps attack steps to adversary tactics, techniques, and procedures (TTPs) from a pluggable set of frameworks (MITRE ATT&CK, CAPEC, and cloud-specific threat matrices), and synthesizes actionable mitigations. ThreatForest decomposes threat modeling into a multi-stage agent pipeline -- repository analysis, context refinement, threat generation, parallel attack-tree construction with TTP mapping and mitigation synthesis, and report generation -- orchestrated as a directed graph with deterministic verification gates, bounded retries, and three human-in-the-loop validation points. A domain-specific sentence-transformer maps each attack step to candidate techniques by cosine similarity; we show empirically that this embedding stage, not the surrounding pipeline, is the dominant accuracy bottleneck. We evaluate ThreatForest across seven application domains on a sixteen-dimension rubric, scored by a panel of independent LLM raters with an adversarial verification pass and expert review. Panel-measured quality reaches 0.63-0.68 (on a 0-1 scale) for threat statements, attack trees, and mitigations, but only 0.29 for embedding-only TTP mapping -- a gap stable across all seven domains that isolates the binding constraint. A controlled single-call baseline on the same model more than doubles mapping defensibility, pinning the limitation on the embedding encoder rather than the multi-agent design. To our knowledge, ThreatForest is the first end-to-end system that turns a code repository into TTP-mapped attack trees with evidence-based mitigations across adversary frameworks, with a reusable framework for benchmarking such systems.

- **核心问题**：如何在不需要稀缺安全专家深度参与的前提下，从源代码仓库自动生成结构化、可操作、符合标准化框架的威胁模型？

## 2. 方法论

**核心思想**：将威胁建模分解为多阶段智能体流水线，以有向图形式编排，每个阶段由 LLM 智能体（生成、推理）+ 确定性验证器（结构校验）组成，并配有有限重试和三个人机协同（HITL）验证点。

**流水线主要阶段**：
- **Scanner Agent**：读取仓库路径，通过结构分析器和沙箱文件读取器提取项目上下文（云提供商、技术栈、服务、认证机制、数据流、部署模型），由确定性验证器检查必填字段。
- **Interviewer Agent**：通过 ask_user 工具向用户进行针对性提问，补充上下文并附置信度。
- **Threat Agent**：生成结构化威胁表述，形式为：
  “A [actor] with [access/knowledge], can [action], which leads to [impact], resulting in [consequence].”
  （某主体拥有某种权限/知识，可执行某动作，导致某影响，最终产生某后果。）
- **Attack Tree Agent（并行子流水线）**：针对每个威胁生成一棵攻击树（根=对手目标，中间节点=AND/OR子目标，叶子=攻击技术）。每个步骤包含 `fact/action/detection/gate` 等类别。形式化定义：树 \( \mathcal{T}_\theta = (S, E, r) \)，深度为最长根到叶路径长度。
- **TTP 映射（嵌入检索）**：使用 ATTACK-BERT（领域特定的 sentence-transformer，输出 768 维嵌入）对攻击步骤和 ATT&CK 技术描述编码，用余弦相似度检索 top-3（阈值为 τ=0.3）。形式：\( \text{sim}(d_i, t_j) = \mathbf{e}(d_i) \cdot \mathbf{e}(t_j) / (\|\mathbf{e}(d_i)\| \|\mathbf{e}(t_j)\|) \)。
- **Mitigation Agent**：针对每个唯一映射技术生成结构化缓解记录（含 technique_id、指导、优先级、证据、类型），证据与具体攻击步骤和技术相连。
- **Verifier Pattern**：每个阶段都有确定性校验器（纯 Python，无 LLM），检查字段完整性、父-子引用、缓解覆盖；结构失败触发重试，覆盖缺失只发软警告（避免整条流水线重跑）。
- **Probability 评分**：纯 Python 阶段用贝叶斯更新加马尔可夫回滚，为每个步骤标注成功概率（fact 类固定为 1.0），得到“到达概率”，报告生成器按最高可达路径优先排序输出。
- **有界重试**：总节点执行预算 \( B \geq |V| + k \cdot |\{retriable\text{ }stages\}| \)，文中配置 \( |V|=12, k=2 \)，上限 \( B=32 \)。
- **三个 HITL 门**：扫描器确认、威胁评审（含四问引导：合理性、优先级、误报、遗漏）、TTP/缓解评审——结构化编辑直接合入状态文件，自由文本反馈则重新调用上游 LLM。

## 6. 主要结论与发现

1. **嵌入检索的 TTP 映射是唯一主导瓶颈**：攻击树、威胁表述、缓解措施评分均在 0.63–0.68，而嵌入映射只有 0.29——7 个领域一致，95% 置信区间 [0.23, 0.35] 与其他能力完全不重叠。
2. **瓶颈在编码器，不在流水线架构**：单体基线 TTP 映射 0.63，是嵌入检索的两倍以上；但流水线赢得覆盖率和结构一致性（240 vs 87 攻击步、89 vs 29 独特技术、0.98 vs 0.85 战术覆盖、深度更均匀）。
3. **现有通用编码器结构性不足**：ATTACK-BERT 恢复正确技术 top-1 达 80%，而 all-mpnet 为 45%、BGE 为 38%、E5 为 34%。
4. **阈值影响覆盖率而非正确性**：τ 从 0.3 提升到 0.4 仅损失 5% 映射，但正确率上限仍由编码器决定。
5. **试点验证了改进方向**：用面板标签微调跨编码器重排序器，使映射判断 F1 从 0.36 提升至 0.51、准确率从 0.52 到 0.82（0.76 精度，0.39 召回）。
6. **成本可控**：约 10 分钟内、约 $8 可完成一个应用的威胁建模——远低于人工多日成本。

## 7. 优点

- **瓶颈隔离贡献**：不是笼统地报告系统效果，而是将核心限制精确定位到一个可替换组件上，直接指引后续研究方向（领域特定编码器微调或 LLM 驱动的映射）。
- **构建了可复用的评估基建**：16 维评分规则、Langfuse 注解队列、开放编写的评分协议（3 评委 + 对抗验证 + SME 仲裁 + 跨模型校准）——未来系统可直接作为 benchmark 参与比较。
- **多轮防御机制完备**：确定性验证器与 LLM 智能体分工明确；重试预算有界（不会无限循环）；文件状态传递使每个中间产物可检视、可恢复；HITL 门支持结构化编辑和自由文本反馈。
- **框架插件化设计**：MITRE ATT&CK、CAPEC、云特定威胁矩阵可互换，无需重训练嵌入模型。
- **充分的消融实验结构**：对每个主要设计决策（嵌入模型、阈值、是否分解流水线）进行了单因子变量控制的验证。
- **评估诚实守正**：对抗验证者只允许降分、面板比独立评委员更保守、TTP 得分被诚实地报告为 0.29 的低值（而非为展示系统而选择性报道）。

## 8. 不足与局限

- **单模型家族依赖**：所有实验仅用 Claude Sonnet 4.5；提示词针对该模型调优，换到较弱模型可能大幅降效，也未测跨厂商能力。
- **LLM 评委员的盲区风险**：评委员与生成器可能共享盲点，虽有小规模跨模型校准（56 项、97.6% 一致性），但完全一致的隐匿缺陷仍可能漏网；人工 SME 仲裁是确认性的而非前提条件。
- **ATT&CK 对云原生覆盖不足**：某些云/无服务器特有技术（如 IAM 信任策略错误配置、Lambda 冷启动竞态）在 ATT&CK 目录中缺乏严格对应，导致检索映射弱化。
- **幻觉风险未量化**：威胁/攻击树步骤由 LLM 生成，文中未独立测量幻觉率，只靠结构化验证和 HITL 门做防御。
- **外部效度有限**：7 个领域均为可单人评审的小型示例系统；真实生产系统更大、更复杂、可能多云，扫描器对未知组件的处理效果未经验证。
- **构造效度问题**：16 个维度间并不独立（如攻击树的技术真实性与威胁表述的技术准确性高度相关），且未进行多 SME 的评分者间信度研究。
- **TTP 映射的有效性严重受限**：0.29 的得分意味着约 7 成映射不可靠，作为系统声称的“可操作输出”在实践上需要大量人工修正才能满足生产要求。
- **覆盖率本身双刃剑**：阈值低、覆盖率高，但大量“弱映射”只是形式上填充了每步技术，对后续缓解的针对性不利（文中也承认这一点）。
