## 摘要
多智能体系统通过任务分解和角色专业化来提升能力，但这些机制也引入了一个重要的安全盲点：一个有害目标可以被分解为局部看似合理的子任务，从而使恶意意图逃避任何单个智能体的检测。这是一个日益增长的社会影响挑战：处理敏感信息或关键工具的系统可能将常规委派转变为未经授权的披露或不安全行为。我们认为，这种失效模式更适合被理解为一种语义信息流问题，而非单轮提示分类任务。为解决这一问题，我们提出了SafeFlow，一种针对多智能体系统的防御框架，将恶意的跨智能体传播形式化为语义信息流问题。SafeFlow将结构化的语义污点附加到根请求上，通过动态协作图传播这些污点，并在执行不可逆操作之前执行工作流级验证，以重建全局风险上下文。在四个基准测试上（涵盖提示注入、基于越狱的不安全工具使用、危险代码执行和有害的网页智能体行为），与未防御的基线和外部防御相比，SafeFlow降低了攻击成功率，同时保持了较高的良性任务完成率和较高的成对安全-有害成功率。我们的研究结果表明，多智能体系统仍然缺乏在委派边界上保留风险语义的机制。这一鸿沟可能将常规委派转变为影响个人和组织的隐私损害或不安全行为。SafeFlow在整个工作流中保持这种风险的可见性，直到风险造成损害之前。

## Abstract
Multi-agent systems improve capability through task decomposition and role specialization, but these same mechanisms introduce an important safety blind spot: a harmful objective can be fragmented into locally plausible subtasks, allowing malicious intent to evade detection by any single agent. This is a growing social-impact challenge: systems handling sensitive information or consequential tools can turn routine delegation into unauthorized disclosure or unsafe action. We argue that this failure mode is better understood as a semantic information-flow problem than as a single-turn prompt classification task. To address this, we propose SafeFlow, a defense framework for multi-agent systems that formalizes malicious cross-agent propagation as a semantic information-flow problem. SafeFlow attaches structured semantic taints to root requests, propagates them through a dynamic collaboration graph, and performs workflow-level validation to reconstruct the global risk context before irreversible actions are committed. Evaluated on four benchmarks spanning prompt injection, jailbreak-based unsafe tool use, risky code execution, and harmful web-agent behavior, SafeFlow reduces attack success rates compared to undefended baselines and external defenses while retaining high benign task completion and a high paired safe--harm success rate. Our findings show that multi-agent systems still lack mechanisms for preserving risk semantics across delegation boundaries. This gap can turn routine delegation into privacy harms or unsafe actions that affect people and organizations. SafeFlow keeps this risk visible throughout the workflow, before it results in harm.

- **典型场景**：一个请求被拆成“检索敏感信息 → 改写内容 → 外部发送”等多个步骤，每一步单独来看都不构成明显违规，组合起来却形成数据窃取或越权操作的完整路径。
- **问题定性**：论文明确指出，这种失效模式不应被建模为“单轮提示分类任务”，而应被理解为**语义信息流（semantic information-flow）问题**——关键在于跨代理、跨工具调用之间风险语义的传播与汇聚，而非单个Prompt是否恶意。
- **社会影响**：系统处理敏感信息或高影响工具时，常规的委派流程可能变成隐私泄露或不安全操作，且受影响的是未编写提示词也未观察工作流的第三方个人和组织。

### 2. 方法论：核心思想、关键技术细节、算法流程

**核心思想**：将恶意跨代理传播建模为语义信息流控制问题，通过在协作图上传播结构化语义污点，延迟裁决直到完整“源—汇”（source–sink）路径被重建后，才决定是否放行。

**环境形式化**：系统模型为 M = (A, U, T, O)，包括智能体集合 A、工具接口 U、规划器 T、可观察执行通道 O。攻击不涉及模型权重或主机级破坏，而是内生性的工作流组合攻击。

**污点标签模式（Taint Semantics）**：默认策略使用7个标签——

- 源标签：SENSITIVE_READ（敏感读取）、CREDENTIAL_ACCESS（凭据访问）
- 汇标签：EXTERNAL_SEND（外部发送）、PRIVILEGED_EXEC（特权执行）、CODE_EXEC（代码执行）、DESTRUCTIVE_WRITE（破坏性写入）
- 控制平面标签：PROMPT_OVERRIDE（提示词覆盖）

**传播规则**：沿委派、消息、重写、摘要边复制活动标签；检索边增加被检索对象的标签；工具边根据归一化能力附加汇标签。传播是单调的，直到明确的释放规则被满足。**模型生成的解释只能提供证据片段，不能清除污点**。

**五阶段架构（即算法流程）**：

1. **意图污点标注（AnnotateIntent）**：通过词法匹配器、受约束的防御侧LLM分类器和工具启发式，为根请求附加结构化污点标签，输出严格JSON格式，不创造标签或释放条件。
2. **规划与污点传播（PlanSubtasks → PropagateTaints）**：LLM生成子任务骨架，PropagateTaints确定性构建污点协作图 G = (V, E, τ)，将不可逆操作置于“暂存”状态。
3. **上下文重建（ReconstructContext）**：为每个图节点生成节点级执行视图，将分布在各消息、检索内容、工具轨迹中的证据聚合成结构化记录。
4. **全局验证（ValidateWorkflow）**：对完整工作流图确定性应用规则集 R，对所有暂存的硬汇做出最终放行或阻止决策。关键的是**缺失的源—汇路径会被判为歧义（ambiguous）而非安全**。
5. **归因感知决策（GenerateAttribution）**：记录决定性路径、触发污点、汇类型、未满足的释放条件，不改变裁决结果。

**条件确定性（Conditional Determinism）**：标注、规划、上下文重建可能随LLM输出变化，但一旦结构化记录固定，传播、暂存、聚合、验证和归因全部是确定性的。

**关键设计点——延迟裁决（Deferred Adjudication）**：许多攻击要等几个独立合理的动作组合成路径后才变得明确，因此SafeFlow不在局部过早裁决，而是等全局路径装配完成后再做决定。

### 6. 主要结论与发现

- **主结果**：无攻击环境中，SafeFlow将平均ASR从69.3%（SafeAgents未防御）降至12.7%，同时在每个基准上取得最高配对成功率（ASB 81.5%、AgentHarm 78.6%、RedCode 80.8%、SafeArena 75.1%）；良性任务保持90%左右TCR，优于GuardAgent和AegisLLM。
- **越狱鲁棒性**：所有越狱攻击都提高ASR，但SafeFlow仍保持最低ASR（JailBroken最强，32.3%；ReNeLLM 25.5%、GPTFuzz 20.9%、MultiLingual 19.1%，对比未防御85.5%）。
- **防御模型无关性**：在6种防御侧LLM上，最高防御平均ASR为12.7%，证明安全增益主要来自工作流级管道而非特定模型校准。
- **消融**：移除规划与污点传播（w/o TP）对ASR影响最大（RedCode和SafeArena上ΔASR最高约30个百分点），证实污点传播是核心支柱。
- **策略丰富度**：从4-Label到14-Label，ASR从22.1%降到8.9%，配对成功率从71.5%升到81.3%；但FPR也随策略丰富度轻微上升，存在校准代价。
- **上下文重构范围**：全上游重构将路径恢复率从63.5%提升到89.2%，ASR从25.4%降至12.4%。
- **局部vs跨代理**：跨代理场景更难防御，但SafeFlow在两类场景都保持最低ASR；对有害工作流的局部放行/全局阻止率达79.1%。
- **自适应攻击**：在三种适应性扰动下维持20.9%–24.5% ASR和72.5%–85.9%的路径恢复率。
- **防御侧注入**：即使防御侧LLM被间接注入影响，污点保留率仍达93.8%–98.3%，路径恢复率84.9%–91.7%。

### 7. 优点：方法与实验亮点

- **问题建模创新**：将多智能体安全性问题重新框定为语义信息流控制问题，跳出了“单PromPT分类”的既有视角，切中了分布式组合攻击的本质。
- **延迟裁决理念**：在不可逆动作提交前保留完整证据链，避免因局部步骤看似合理而过早放行，是安全性架构上的关键设计选择。
- **确定性安全边界**：传播、暂存、验证和归因在结构固定后完全确定，LLM只承担证据提取角色，不能自行清除污点或发明释放条件，安全核心不依赖于LLM的临时判断。
- **严格输出契约**：结构化JSON输出模式（标注和重建均有限定模式），拒绝未知标签，缺少授权元数据时保持暂存（fail-closed），实用性强。
- **全面且配置周到的实验**：覆盖安全性（ASR）、实用性（TCR/FPR）、配对成功（Paired）多个维度；在无攻击、越狱攻击、自适应攻击、间接注入四种威胁下测试；消融实验验证了各阶段贡献；策略模式可配置性体现了实际部署的灵活性。

### 10. 综合评价

- **一句话评价**：SafeFlow是首个系统性地将多智能体安全重构为**语义信息流控制**问题、并提出**延迟全局裁决**架构的工作，问题定义准确、架构设计巧妙，在多个安全基准上取得了一致且显著的改进，学术价值与工程启发意义兼备。
- **学术贡献**：① 首次明确提出跨代理语义污点传播的安全模型与形式化框架；② 提供"延迟裁决"这一可泛化的防御范式（先装配完整路径、再判决放行/阻止），与现有逐轮检测思路形成本质区别；③ 建立覆盖无攻击、越狱、自适应、间接注入四类威胁的评估体系，为后续研究提供了可对比的基准与方法论模板。
- **工程价值**：采用"确定性核心 + LLM证据提取"的混合架构，安全关键路径不依赖LLM的主观判断；严格JSON契约与fail-closed策略（缺少授权元数据时保持暂存）使其具备实际部署可行性。
- **局限总评**：安全性与实用性之间存在明确张力（策略越丰富、防御越强但FPR越高）；对运行时可观测性的强依赖限制了其在不可信、异构或部分无插桩环境中的适用性；基准规模偏小限制了结论的外推空间。

### 11. 对后续研究的启示

- **信息流安全作为新范式**：本研究提示多智能体安全研究可从"判断单个Prompt是否有害"转向"追踪语义与数据的传播路径"，这为对抗分布式、组合式攻击提供了更本源的思路。
- **延迟裁决的可扩展性**：在拥有数十甚至上百个智能体、长时间运行的真实Agent生态中，如何高效地维护污点图、压缩证据链、控制延迟裁决带来的暂存资源开销，是值得探索的开放问题。
- **防御侧组件的加固**：既然上下文重建环节仍依赖LLM，如何通过可验证推理、结构化解析、检索增强或小型确定性模型替代，降低该环节的脆弱性与被注入面，是自然的延伸方向。
- **误报控制的进阶方案**：在更丰富污点策略与更低FPR之间寻求平衡，例如引入概率性污点置信度、用户级授权元数据预加载或交互式澄清机制，可作为后续实用性研究方向。

---

**总结**：SafeFlow通过将多智能体安全重新定义为语义信息流控制问题，并以"污点传播 + 延迟裁决 + 确定性验证"的组合方案，在四个主流安全基准上显著降低了攻击成功率（平均ASR从69.3%降至12.7%），同时保持了对良性任务的高完成率与可接受的误报率。其核心贡献在于架构层面的范式转换——不再对单步Prompt做孤立判决，而是等待完整源—汇路径装配后做全局裁决。尽管存在算力信息缺失、基准规模有限、对可观测性依赖强、防御侧LLM仍是攻击面等局限，该工作仍为多智能体系统安全提供了极具启发性的新框架，并为后续研究指明了信息流安全、可扩展污点追踪与防御侧组件加固等重要方向。
