## 摘要
在过去的十年中，我们见证了深度学习模型、平台和应用的指数级增长。虽然现有的深度学习应用和机器学习即服务（MLaaS）框架假设模型完全可信，但隐私保护的DNN评估需求逐渐出现。在安全多方计算场景中，模型和数据均被视为专有，即模型所有者不希望向用户泄露高价值的深度学习模型，而用户也不愿披露其私人数据样本。传统的隐私保护深度学习解决方案要求用户将加密样本发送给模型所有者，后者必须承担同态加密下密文域计算的繁重工作。本文提出了一种新颖的解决方案PrivDNN，它通过（1）与用户共享加密深度学习模型，将计算卸载到用户端；（2）使用部分DNN加密显著提高DNN评估效率；（3）通过核心神经元选择和加密方案确保模型准确性和模型隐私。实验结果表明，PrivDNN在保持模型性能和隐私的同时，将隐私保护DNN推理时间和内存需求降低了高达97%。代码可在https://github.com/LiangqinRen/PrivDNN获取。

## Abstract
In the past decade, we have witnessed an exponential growth of deep learning models, platforms, and applications. While existing DL applications and Machine Learning as a service (MLaaS) frameworks assume fully trusted models, the need for privacy-preserving DNN evaluation arises. In a secure multi-party computation scenario, both the model and the data are considered proprietary, i.e., the model owner does not want to reveal the highly valuable DL model to the user, while the user does not wish to disclose their private data samples either. Conventional privacy-preserving deep learning solutions ask the users to send encrypted samples to the model owners, who must handle the heavy lifting of ciphertext-domain computation with homomorphic encryption. In this paper, we present a novel solution, namely, PrivDNN, which (1) offloads the computation to the user side by sharing an encrypted deep learning model with them, (2) significantly improves the efficiency of DNN evaluation using partial DNN encryption, (3) ensures model accuracy and model privacy using a core neuron selection and encryption scheme. Experimental results show that PrivDNN reduces privacy-preserving DNN inference time and memory requirement by up to 97% while maintaining model performance and privacy. ## 1. 核心问题与整体含义（研究动机和背景）

- 深度学习模型（DNN）在图像分类、医疗、金融等领域广泛应用，但模型训练需要大量数据和算力，导致小机构希望以服务方式使用大公司的高精度模型。
- 在安全多方计算场景下，**模型所有者和数据所有者双方互不信任**，需要同时保护模型隐私（模型参数不被泄露）和数据隐私（用户数据不被模型所有者知晓）。
- 现有隐私保护DNN方案（如CryptoNets）采用**数据加密**方式：用户加密数据后发送给模型所有者，模型方在密文域执行全部推理。该方式计算开销巨大（CryptoNets评估一个MINST批次需250秒），且全部计算由模型方承担，模型方缺乏激励。
- **模型加密**方式（将加密模型发送给用户执行推理）可对称地分担计算压力，但现有全模型加密方案同样面临极端低效问题。
- 核心问题：**如何在保证模型和数据隐私的前提下，大幅降低隐私保护DNN评估的计算和内存开销**。

## 2. 方法论

### 核心思想
- 采用**部分DNN加密**：并非加密整个模型，而是仅加密对模型性能**最关键的神经元子集**（核心神经元），其余神经元保持明文。
- 将部分加密的模型发送给数据所有者，**将大部分计算卸载到用户侧**：明文部分用普通计算，密文部分用同态加密（FHE）计算。
- 授权用户可通过解密核心神经元的输出结合明文部分获得高精度；未授权用户（无法解密）仅能利用明文部分，精度大幅下降。

### 关键技术细节
1. **FHE友好DNN设计**：仅对加密神经元使用FHE兼容的激活函数（论文选用平方函数），明文部分可使用ReLU等标准激活函数，减少精度损失。
2. **核心神经元选择**：提出四个算法（后两个为本文重点）：
   - **随机选择**（基线）：从指定层随机选择神经元。
   - **贪心选择**：逐层、逐神经元评估候选神经元加入核心集后的质量分数 \( s \)（公式1），选择best neuron，复杂度高但质量最优。
   - **剪枝选择**：利用现有结构化剪枝算法（PFEC, FPGM, HRank, GFS）识别“重要”神经元作为核心集，速度快但质量略低。
   - **剪枝+贪心组合**：先用剪枝缩小候选池（池大小为2倍目标核心数），再在池内运行贪心算法，平衡效率与质量。
3. **质量分数定义**：
   \[
   s = -\text{sigmoid}(A_o - A_s) + \text{sigmoid}\left(\frac{A_s - A_r}{\alpha}\right)
   \]
   其中 \(A_o\) 原始准确率，\(A_s\) 授权评估准确率，\(A_r\) 未授权准确率，\(\alpha=5\)（经验值）。该分数激励 \(A_s\) 接近 \(A_o\) 且 \(A_r\) 远低于 \(A_s\)。
4. **部分加密执行流程**：
   - 初始化阶段：模型所有者训练FHE友好模型 → 选择核心神经元 → 使用CKKS同态加密核心神经元 → 发送部分加密模型给用户。
   - 评估阶段：用户混合推理（明文+密文） → 将加密核心输出混淆后发给模型所有者解密 → 返回去混淆后的结果 → 用户继续推理剩余层。
5. **防御恶意攻击**（可选）：添加服务器端混淆层（卷积层），权重对用户保密，消除用户通过解密服务器回传结果窃取模型参数的风险。

## 6. 主要结论与发现

1. **效率提升显著**：PrivDNN将隐私保护DNN推理时间和内存需求降低高达97%（相比全加密）。例如MNIST LeNet-5：全加密5647秒 vs 部分加密190秒。
2. **核心选择有效性**：贪心算法可稳定选出高质量核心集（13/18次为最优，其余前3），显著优于随机。剪枝+贪心组合在效率与性能之间取得平衡。
3. **安全目标达成**：仅加密15%~25%的首两层神经元，即可使未授权准确率下降20%以上（如CIFAR10 50%加密时\(A_r\)=55.9%）；加密75%以上时\(A_r\)可降至10%以下。
4. **模型恢复攻击抵抗**：即使在加密比例较低时，恢复攻击得到的模型准确率仍明显低于原始模型（如CIFAR10 50%加密时，恢复后准确率83.6% vs 原始90.22%）；加密比例越高，恢复越困难。
5. **样本恢复攻击抵抗**：即使模型所有者获得所有层2输出（混淆后），也无法恢复有意义原始图像（分割学习、自编码器均失败）。

## 7. 优点

- **创新性**：首次提出“部分DNN加密”思想，指出保护模型时无需加密所有参数，从效率瓶颈入手突破，思路新颖且实用。
- **方法完整性**：设计了从核心选址、加密部署、执行流程到安全防御的完整框架，且不依赖特定FHE算法或DNN架构，可适配多种方案。
- **实验丰富**：在5个标准数据集、多种模型上验证，并包含穷举搜索作为ground truth，对比了多种核心选择算法，攻击实验覆盖双方向攻击。
- **实用性**：代码开源（GitHub），内存需求大幅降低（全加密VGG16需151GB内存而PrivDNN仅需2.5~5GB），使受限用户（小企业）也能部署。
- **性能-安全性权衡分析**：给出了选择不同加密比例时准确率、恢复抵抗、时间的量化曲线，便于模型所有者根据需求调整参数。

## 8. 不足与局限

- **假设局限**：主要考虑半诚实（honest-but-curious）模型，对恶意用户/服务器防御较弱，虽然提出了服务器端混淆层防御，但未全面分析恶意场景下安全性。
- **FHE友好性限制**：加密部分需使用FHE兼容激活函数（平方函数），可能影响模型精度（实验中通过训练从零适应，但若迁移预训练模型需微调）。
- **核心选择开销**：贪心算法在复杂模型上耗时巨大（如GTSRB选择75%神经元需121636秒≈1.4天），虽是一次性开销，但实际部署中可能不可接受；剪枝+贪心虽快，但质量略有下降。
- **数据集规模局限**：实验仅使用小到中等规模数据集（最大Tiny-ImageNet 200类），未在ImageNet等大规模数据集上验证框架可扩展性。
- **通信开销未分析**：未考虑模型分发、解密交互的网络传输时间，这在真实分布式场景中可能成为瓶颈。
- **攻击假设较强**：模型恢复攻击假设攻击者拥有100~1000个带标签样本，且需使用全部样本微调；实际中攻击者可能拥有更多样本或利用更灵活的方法（如无数据模型窃取），论文未深入讨论高资源攻击者场景。
- **对照方法单一**：核心选择对比中仅包含随机和四种剪枝算法，未与直觉式（如固定位置加密）或更先进的选择策略（如基于梯度、基于注意力）比较。
- **硬件环境单机**：所有实验在同一台桌面计算机上进行，未在分布式/云环境验证内存和计算效率的实际影响。
